**An AI-powered Document Question Answering System using Hybrid Retrieval, Local Large Language Models, and Retrieval-Augmented Generation (RAG).**


**From hours to highlights — AI summaries for every format.**

An AI-powered app that transforms **YouTube videos, PDFs, and meeting transcripts** into clear, concise summaries using advanced **NLP models** and **Retrieval-Augmented Generation (RAG)**.

# Problem Statement

With the rapid growth of digital information, users often work with large documents such as research papers, reports, presentations, manuals, and datasets. Finding specific information within these documents can be time-consuming, especially when users need to manually search through multiple files.

Traditional document readers allow users to view and search documents using simple keyword matching, but they cannot understand the meaning of a user's question or provide context-aware answers. Similarly, general-purpose AI chatbots cannot answer questions about private or user-uploaded documents because they do not have access to the document contents unless the information is explicitly provided.

Another challenge is that cloud-based AI solutions often require users to upload confidential documents to external servers, raising concerns about data privacy, security, internet dependency, and operational costs.

Therefore, there is a need for an intelligent document question-answering system that can:

- Process multiple document formats.
- Understand natural language questions.
- Retrieve relevant information from uploaded documents.
- Generate context-aware answers based only on the document content.
- Operate locally without relying on cloud-based AI services.
- Provide an interactive and user-friendly interface for document interaction.

This project addresses these challenges by combining Retrieval-Augmented Generation (RAG), hybrid document retrieval, and a locally hosted Large Language Model to create an efficient AI-powered document assistant.

# How the Project Solves the Problem

The Intelligent Multi-Document AI Assistant addresses the limitations of traditional document search systems by integrating document retrieval and natural language generation into a single application.

Instead of searching documents using only exact keywords, the application first extracts textual content from uploaded documents and converts it into searchable representations. The extracted text is divided into smaller chunks to improve retrieval efficiency and ensure that only relevant sections of a document are considered during question answering.

To retrieve relevant information, the application uses a hybrid retrieval strategy that combines two complementary retrieval methods.

The first method uses FAISS with sentence embeddings generated by the Sentence Transformer model (`all-MiniLM-L6-v2`). This enables semantic search, allowing the system to retrieve information based on the meaning of the user's query rather than requiring exact keyword matches.

The second method uses the BM25 retrieval algorithm, which performs keyword-based matching. BM25 is effective when users search for specific terms, names, abbreviations, or technical vocabulary.

The results returned by FAISS and BM25 are combined, duplicate document chunks are removed, and the most relevant context is selected. This retrieved context is then incorporated into a prompt together with the user's question and recent conversation history.

The prompt is sent to the Mistral Large Language Model running locally through Ollama. Instead of answering solely from its pre-trained knowledge, the language model generates responses using the retrieved document context, making the answers relevant to the uploaded documents.

The generated response is streamed to the user through a Streamlit-based web interface, providing an interactive conversational experience. The application also maintains session-based conversation history, enabling users to ask follow-up questions while preserving context during the active session.

Because the language model runs locally using Ollama, document processing does not require external AI APIs. This allows users to work with their documents without depending on cloud-based services and keeps document processing within the local environment.

By combining document parsing, semantic retrieval, keyword retrieval, prompt construction, conversational memory, and local language model inference, the application provides an efficient and practical solution for document-based question answering.

# System Architecture

The Intelligent Multi-Document AI Assistant follows a Retrieval-Augmented Generation (RAG) architecture that combines document processing, hybrid information retrieval, and local language model inference. The architecture is designed to retrieve relevant information from uploaded documents before generating responses, ensuring that answers are based on the document content rather than relying only on the pre-trained knowledge of the language model.

The system consists of the following major components:

## 1. User Interface

The user interface is developed using **Streamlit**, providing a simple and interactive web application.

The interface allows users to:

- Upload one or more documents.
- Select a specific document or search across all uploaded documents.
- Enter questions in natural language.
- View AI-generated responses in a conversational format.
- Stream responses in real time.

---

## 2. Document Processing Module

After a document is uploaded, the system automatically extracts its textual content.

Different libraries are used depending on the document format.

| Document Type | Processing Library |
|---------------|--------------------|
| PDF | PyPDF |
| DOCX | python-docx |
| PPTX | python-pptx |
| CSV | Pandas |
| TXT | UTF-8 Text Reader |

The extracted text becomes the input for the Retrieval-Augmented Generation pipeline.

---

## 3. Text Chunking Module

Large documents cannot be directly processed efficiently during retrieval.

To overcome this limitation, the extracted text is divided into smaller overlapping chunks using LangChain's Recursive Character Text Splitter.

Current configuration:

- Chunk Size: 500 characters
- Chunk Overlap: 50 characters

Chunking improves retrieval performance because the retrieval system searches smaller sections of a document rather than the entire document.

---

## 4. Embedding Generation Module

Each text chunk is converted into a numerical vector representation using the Sentence Transformer embedding model.

Embedding Model:

sentence-transformers/all-MiniLM-L6-v2

These embeddings capture the semantic meaning of the document rather than simply matching keywords.

The generated embeddings are stored in a FAISS vector index.

---

## 5. Hybrid Retrieval Module

The retrieval component combines two independent retrieval techniques.

### Dense Semantic Retrieval

The FAISS vector database retrieves document chunks whose embeddings are most similar to the user's question.

This enables semantic matching.

For example,

Question:

"What are the advantages of machine learning?"

can retrieve text containing

"Benefits of artificial intelligence"

even if the exact words are different.

---

### Sparse Keyword Retrieval

The BM25 retriever performs lexical search.

It retrieves document chunks based on keyword frequency and relevance.

BM25 performs well when the query contains

- exact terminology
- names
- abbreviations
- technical vocabulary

---

### Hybrid Search

The outputs from FAISS and BM25 are combined.

Duplicate document chunks are removed.

The final set of retrieved chunks is used as contextual information for answer generation.

Using both retrieval methods helps improve retrieval quality by combining semantic understanding with keyword matching.

---

## 6. Prompt Construction Module

After retrieving the most relevant document chunks, the application constructs a prompt.

The prompt consists of three parts:

- Previous conversation history
- Retrieved document context
- User's current question

This prompt provides the language model with the necessary information to generate document-grounded responses.

---

## 7. Large Language Model

The project uses the **Mistral** Large Language Model through **Ollama**.

The language model runs locally on the user's computer.

The prompt constructed by the application is sent to Ollama, which forwards it to the Mistral model for response generation.

Running the model locally removes the dependency on external AI APIs.

---

## 8. Response Streaming

Instead of waiting for the complete response, the application streams the generated answer incrementally.

This provides a smoother user experience and allows users to begin reading the response immediately.

---

## 9. Conversational Memory

The application maintains session-based conversation history using Streamlit Session State.

Separate conversation history is maintained for:

- Individual uploaded documents
- All uploaded documents combined

Recent interactions are included in future prompts, allowing users to ask follow-up questions within the same session.

# Design Decisions

Several design choices were made during the development of this project to improve usability and retrieval quality.

### Hybrid Retrieval

Instead of relying on only semantic search or only keyword search, both FAISS and BM25 are combined to retrieve more relevant document chunks.

### Local Language Model

The application uses Ollama with the Mistral model to perform inference locally. This removes the dependency on cloud-based AI services and enables offline execution after the required model has been installed.

### Recursive Text Chunking

Documents are divided into overlapping chunks before indexing. This improves retrieval accuracy by allowing the system to search smaller sections of text instead of entire documents.

### Session-Based Memory

Conversation history is maintained within the active Streamlit session to support follow-up questions without requiring users to repeat previous context.

### Streaming Responses

Responses are displayed incrementally as they are generated, improving the overall user experience by reducing perceived waiting time.
